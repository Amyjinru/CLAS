# UC06 商家入驻申请与管理员审核开店

## 用例说明

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC06 |
| 主要参与者 | 申请人、管理员 |
| 协作参与者 | 验证码存储、用户账号服务、商家服务 |
| 触发条件 | 申请人提交入驻资料；管理员提交审核状态与备注 |
| 前置条件 | 游客已取得账号手机号验证码并提供合法账号信息，或申请人已登录；商家资料含名称、联系电话、分类、地址和地图坐标；管理员已登录且角色为 `ADMIN` |
| 后置条件 | 新商家以 `PENDING` 保存；合法审核操作更新状态和备注，并追加不可混淆的审核日志；达到 `OPEN` 后可对外营业 |

### 主成功流程

1. `UC06-F01` 申请人进入入驻表单并填写账号/商家资料和地图位置。
2. `UC06-F02` 游客先获取并提交验证码；已登录用户沿用当前账号。
3. `UC06-F03` 系统校验账号、密码、联系电话、店名唯一性、一人一店和地图坐标。
4. `UC06-F04` 系统必要时创建或升级为 `MERCHANT` 账号，并创建状态为 `PENDING` 的商家。
5. `UC06-F05` 申请人查看审核状态、管理员备注与时间线。
6. `UC06-F06` 管理员在审核列表查看详情并提交合法目标状态和备注。
7. `UC06-F07` 系统更新商家状态，追加包含管理员、前后状态、备注和时间的审核日志。
8. `UC06-F08` 管理员按状态机将 `APPROVED` 商家开通为 `OPEN`。

### 备选或异常流程

- `UC06-A01` 游客验证码错误、密码不合规或两次密码不同，拒绝申请。
- `UC06-A02` 申请人已有商家、店名重复或联系电话重复，拒绝申请。
- `UC06-A03` 缺少合法地图坐标时拒绝申请。
- `UC06-A04` 非管理员调用审核接口时返回 403。
- `UC06-A05` 商家不存在或状态转换非法时拒绝审核，不写入成功日志。
- `UC06-A06` 管理员可将违规商家转为 `BLOCKED`，并可按规则恢复到 `APPROVED`、`CLOSED` 或 `OPEN`。

### 可验证结果

- `UC06-V01` 商家与账号均存在且 `merchant.user_id` 指向申请人。
- `UC06-V02` 新商家状态为 `PENDING`，`manual_closed=false`。
- `UC06-V03` 每次成功审核都存在一条相同商家、管理员、前后状态和备注的日志。
- `UC06-V04` 非法转换前后商家状态不变，且不新增审核日志。
- `UC06-V05` 申请人审核状态页与管理员审核详情显示一致的状态和时间线。

## ADDED Requirements

### Requirement: UC06-R01 申请人账号识别
系统 SHALL 支持游客创建或复用账号后申请入驻，也 SHALL 支持已登录用户直接申请，并 SHALL 将普通用户角色升级为 `MERCHANT`。

#### Scenario: 游客创建账号并申请
- **WHEN** 游客提供有效验证码、合规密码、确认密码、展示名和商家资料
- **THEN** 系统创建 `MERCHANT` 账号并将商家绑定到该账号

#### Scenario: 已登录普通用户申请
- **WHEN** 已登录 USER 提交合法入驻资料
- **THEN** 系统沿用当前账号、升级角色并创建其商家

#### Scenario: 游客凭据无效
- **WHEN** 验证码、密码规则、确认密码或既有账号密码校验失败
- **THEN** 系统拒绝创建商家

### Requirement: UC06-R02 入驻资料和唯一性
系统 SHALL 校验联系电话、店铺名称、地图坐标和一人一店约束，并 SHALL 以 `PENDING` 和未手动打烊状态创建商家。

#### Scenario: 合法资料创建待审核商家
- **WHEN** 申请人的店名、联系电话和地图坐标合法且不存在重复绑定
- **THEN** 系统创建 `PENDING` 商家并设置 `manualClosed=false`

#### Scenario: 重复或不完整资料
- **WHEN** 用户已有商家、店名或联系电话被占用，或地图坐标缺失
- **THEN** 系统拒绝申请并返回具体业务错误

### Requirement: UC06-R03 管理员审核授权和状态机
系统 SHALL 仅允许 ADMIN 审核商家，并 SHALL 按 `PENDING`、`APPROVED`、`OPEN`、`CLOSED`、`BLOCKED` 状态机校验转换。

#### Scenario: 待审核商家获得批准
- **WHEN** ADMIN 将 `PENDING` 商家更新为 `APPROVED`
- **THEN** 系统保存新状态和审核备注

#### Scenario: 已批准商家开店
- **WHEN** ADMIN 将 `APPROVED` 商家更新为 `OPEN`
- **THEN** 商家进入可营业状态

#### Scenario: 非法状态转换
- **WHEN** ADMIN 提交当前状态不允许的目标状态
- **THEN** 系统拒绝转换且不改变商家状态

#### Scenario: 非管理员审核
- **WHEN** USER 或 MERCHANT 调用审核接口
- **THEN** 系统返回无权限结果

### Requirement: UC06-R04 审核日志与申请人可见性
系统 SHALL 为每次成功审核追加审计日志，并 SHALL 向申请人提供当前状态、管理员备注和审核时间线。

#### Scenario: 成功审核写入日志
- **WHEN** 管理员完成一次合法状态更新
- **THEN** 系统记录商家、管理员、旧状态、新状态、备注和创建时间

#### Scenario: 申请人查看审核进度
- **WHEN** 已入驻商家账号请求本人审核状态
- **THEN** 系统返回当前状态、管理员备注和按时间可追溯的审核记录
