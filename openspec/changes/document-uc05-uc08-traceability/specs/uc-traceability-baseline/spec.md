# UC05–UC08 文档与追溯基线

## ADDED Requirements

### Requirement: TR-R01 完整用例说明
每个用例文档 MUST 明确记录参与者、触发条件、前置条件、主成功流程、备选或异常流程、后置条件和可验证结果。

#### Scenario: 审阅任一用例
- **WHEN** 审阅者打开 UC05、UC06、UC07 或 UC08 规格
- **THEN** 审阅者可在单一规格中找到全部必需用例字段和唯一编号的流程/结果

### Requirement: TR-R02 双向追溯
文档 MUST 以稳定标识将需求和流程映射到设计图、API/代码符号、数据对象和测试用例，并 MUST 支持从测试反查需求。

#### Scenario: 从需求追到验证
- **WHEN** 审阅者选择任一 `UCxx-Ryy` 需求
- **THEN** 追溯矩阵给出至少一个设计标识、实现符号和测试标识

#### Scenario: 从测试反查需求
- **WHEN** 审阅者选择任一 `UT`、`API` 或 `E2E` 测试标识
- **THEN** 测试目录给出其验证的需求、前置数据、操作和预期结果

### Requirement: TR-R03 测试证据状态
文档 MUST 将“已有测试代码”“计划补充测试”“已执行结果”分别记录，且 MUST NOT 将未执行测试标记为通过。

#### Scenario: 文档阶段未执行测试
- **WHEN** 本变更只完成文档且未运行测试命令
- **THEN** 测试状态标记为 `已有-未复跑` 或 `待实现-未执行`，执行结果保持空白

### Requirement: TR-R04 可运行性说明
文档 MUST 记录系统运行依赖、启动步骤、演示角色、关键入口和未来验证命令，以便后续测试阶段可重复执行。

#### Scenario: 测试人员准备环境
- **WHEN** 测试人员按运行说明配置 MySQL、Redis、后端和前端
- **THEN** 其可使用演示账号进入 UC05–UC08 对应页面并按测试目录执行验证
