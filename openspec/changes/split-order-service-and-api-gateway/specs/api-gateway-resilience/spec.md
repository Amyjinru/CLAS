## ADDED Requirements

### Requirement: 公开 API 兼容路由
系统 SHALL 提供 API 网关，将既有 `/api/order/**`、`/api/product/**` 与 `/api/merchant/**` 公开路径分别路由到订单、商品目录和商家服务，而无需修改前端调用路径。

#### Scenario: 通过网关访问订单接口
- **WHEN** 客户端请求既有的 `/api/order/**` 路径
- **THEN** 网关将请求路由至订单服务并返回与直接服务调用语义一致的响应

### Requirement: JWT 与请求关联传播
API 网关 SHALL 校验需认证路径的 Bearer JWT，向下游透传有效认证上下文，并生成或保留 `X-Request-Id`。网关与下游服务日志和响应 MUST 包含同一请求标识；下游服务仍 MUST 复核角色与资源归属。

#### Scenario: 已认证请求的关联追踪
- **WHEN** 客户端携带有效 Bearer JWT 和自定义 `X-Request-Id` 请求受保护接口
- **THEN** 网关将请求转发至下游，响应和各服务日志均可用该请求标识关联

#### Scenario: 无效令牌被网关拒绝
- **WHEN** 客户端使用缺失、过期或无效的 Bearer JWT 请求受保护接口
- **THEN** 网关在不转发业务请求的前提下返回认证失败响应

### Requirement: 限流、超时与受控失败响应
API 网关 SHALL 为下游路由配置超时，并实现限流和熔断、备用结果或隔离中的至少一种失败保护。下游不可达、超时或熔断打开时，网关 MUST 返回不泄露内部细节的 `503` 响应及请求标识。

#### Scenario: 下游服务不可用
- **WHEN** 已路由的业务服务停止或在超时窗口内不响应
- **THEN** 网关返回受控 `503` 和 `X-Request-Id`，其它业务路由及健康检查保持可用

#### Scenario: 请求超过限流阈值
- **WHEN** 同一限流键在限定窗口内超过配置阈值
- **THEN** 网关拒绝超额请求并返回可识别的限流响应，且不转发超额流量

### Requirement: 网关部署与可诊断性
API 网关 SHALL 独立构建、测试、容器化和部署，并暴露健康检查、服务版本和路由诊断所需的非敏感信息。交付 MUST 包含一次可重复的失败排查记录和恢复步骤。

#### Scenario: 部署后的路由诊断
- **WHEN** 网关部署至目标环境后执行健康检查和三条业务路由探测
- **THEN** 操作者可确认网关版本、健康状态、目标服务状态和失败请求的关联日志
