## ADDED Requirements

### Requirement: 订单履约服务的独立运行与数据所有权
系统 SHALL 提供可独立构建、测试、容器化和部署的订单履约服务。该服务 MUST 是 `orders`、`order_item`、`order_lifecycle_event` 与 `order_refund_dispute` 的唯一写入者，并使用其私有 schema 或等价数据库隔离。

#### Scenario: 独立服务验证
- **WHEN** 在不启动单体后端的环境中构建并启动订单履约服务
- **THEN** 构建、服务健康检查和订单服务测试均成功，且订单相关写操作只经该服务执行

### Requirement: 下单快照与受控跨服务查询
订单履约服务 SHALL 通过受保护的商品目录和商家内部接口校验下单条件，并在本地事务中固化商品、价格、商家和配送快照。订单服务 MUST NOT 直接读取或写入商品、商家、购物车、支付或配送服务的数据库表。

#### Scenario: 成功创建订单
- **WHEN** 已认证用户使用有效商品和营业中商家提交下单请求
- **THEN** 服务通过内部契约取得校验结果，保存订单及订单项快照，并返回与现有公开 API 兼容的订单结果

#### Scenario: 商品或商家校验失败
- **WHEN** 商品目录或商家服务返回不可售、非营业或无权结果
- **THEN** 订单服务不写入订单数据，并返回可识别的业务失败结果

### Requirement: 订单状态协同的幂等与失败边界
订单履约服务 SHALL 仅接受合法状态转换，并对支付、配送等外部状态通知按来源和事件标识去重。内部调用 MUST 配置连接与读取超时；调用失败时不得产生部分完成的订单状态。

#### Scenario: 重复支付成功通知
- **WHEN** 订单服务收到同一事件标识的两次支付成功通知
- **THEN** 订单状态只推进一次，时间线只记录一次，重复请求返回幂等结果

#### Scenario: 外部依赖超时
- **WHEN** 创建订单所需的内部依赖在配置的超时内未响应
- **THEN** 服务不创建部分订单，返回受控可重试错误并记录请求关联标识

### Requirement: 退款与时间线的授权回归
订单履约服务 SHALL 保持用户、商家、骑手和管理员对订单详情、退款和时间线的角色及资源归属限制，并覆盖主成功、异常授权和非法状态跃迁。

#### Scenario: 越权退款被拒绝
- **WHEN** 非订单所有人或非所属商家请求退款或处理退款
- **THEN** 服务拒绝请求且订单、退款争议和时间线均不被修改
