## Why

当前 CLAS 仅有一个 Spring Boot 单体，订单相关写入与商品、商家、支付、配送逻辑共用同一进程和数据库。后五天看板的 W2-ORDER-01 与 W2-GATEWAY-01 要求以可独立验证的订单服务和统一入口证明服务边界、调用失败保护与公开接口兼容性；现有微服务设计仅为蓝图，尚无工程实现。

## What Changes

- 新建可独立构建、测试、容器化和部署的订单履约服务，承接订单创建、订单状态机、退款争议与时间线。
- 将 `orders`、`order_item`、`order_lifecycle_event` 和 `order_refund_dispute` 的唯一写入权迁至订单服务；创建订单时通过受控内部契约取得并固化商品、商家快照。
- 为支付和配送状态回调定义幂等、超时和失败处理边界，禁止订单服务跨服务直接访问其它领域表。
- 新建 API 网关，保持既有 `/api/**` 公开路径兼容，并至少路由订单、商品目录和商家三个业务服务。
- 在网关统一处理 JWT 校验与透传、请求 ID、限流及服务不可用时的受控响应；服务间 HTTP 调用配置明确超时。
- 补充可复现的集成、端到端、故障排查和部署证据。

## Capabilities

### New Capabilities

- `order-fulfillment-service`: 订单领域的独立写入、跨服务快照、状态协同与退款处理。
- `api-gateway-resilience`: 兼容公开 API 的网关路由、认证传播、请求关联、限流与失败保护。

### Modified Capabilities

- 无。

## Impact

- 新增订单服务、API 网关及其 Maven/容器/Kubernetes 配置；订单相关单体代码将作为迁移来源并在切换后收敛。
- 依赖 W2-ARCH-01 的服务骨架，以及 W2-CATALOG-01、W2-MERCHANT-01 提供的内部查询契约；支付、配送服务需要提供或消费约定的订单事件/回调。
- 前端调用保持 `/api/**` 不变；CI/CD、服务划分文档、数据库迁移、测试和故障证据需同步更新。
