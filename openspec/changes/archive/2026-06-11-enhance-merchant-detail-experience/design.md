## Context

成员 A 当前负责用户发现与个人中心相关体验。本变更聚焦用户端商家详情页，它位于首页搜索之后、加入购物车之前，是用户决定是否购买的关键页面。

当前状态：

- `MerchantDetailView.vue` 已经能加载商家详情、商品列表、收藏状态、购物车、配送估算和地图组件。
- 商品公开列表由 `/api/product/list/{merchantId}` 提供，仅返回 `ON_SALE` 商品。
- 商家详情响应已包含分类、地址、营业时间、配送费、起送价、人均价、评分、配送半径、经纬度等信息。
- 详情页当前信息展示较简单，商品描述、库存、配送状态、收藏状态和空/加载/错误状态不够清晰。

目标体验：

```text
用户从首页进入商家详情
  -> 看到清晰的店铺头部信息、评分、营业时间、配送规则
  -> 看到当前位置/配送距离/预计时间/是否可配送
  -> 看到商品名称、描述、价格、库存/售罄状态
  -> 可收藏/取消收藏并获得明确反馈
  -> 商品为空或加载失败时有清晰提示
  -> 原有加入购物车和提交订单流程保持不变
```

## Goals / Non-Goals

**Goals:**

- 提升商家详情页的信息层次和可读性。
- 明确展示营业时间、起送价、配送费、配送范围、人均价、评分等关键购买决策信息。
- 明确展示当前位置和配送估算结果。
- 改善商品列表展示：描述、价格、库存、售罄、图片/占位。
- 增加加载、空状态、错误提示和收藏操作反馈。
- 保持变更范围主要在 `MerchantDetailView.vue`。

**Non-Goals:**

- 不改购物车、下单、支付、退款的业务规则。
- 不新增商品分类、规格、多 SKU。
- 不新增图片上传或真实对象存储。
- 不改商家后台商品管理。
- 不改管理后台。
- 不改数据库 schema。
- 不依赖高德地图必须成功；地图/定位失败时要能降级。

## Decisions

### Decision 1: 复用现有接口，不新增详情 API

现有 `getMerchant`、`listProducts`、`getDeliveryEstimate`、`listFavorites` 已能提供详情页所需数据。本次主要是前端组合展示和状态管理。

备选方案：新增聚合接口一次返回商家、商品、收藏和配送估算。暂不采用，因为会增加后端改动和与其他成员的冲突。

### Decision 2: 商品仅展示公开上架商品

公开商品接口只返回 `ON_SALE` 商品，这符合用户端体验。用户端只需要处理 `stock <= 0` 的售罄状态。

备选方案：展示下架商品并标记不可买。暂不采用，因为下架商品属于商家管理域，不应出现在用户购买页。

### Decision 3: 配送状态作为购买决策信息展示，但不改变下单规则

详情页可展示可配送/超出配送范围/未选择位置等信息，但是否允许下单、配送费计算等交易规则不在本变更中修改。

备选方案：详情页直接禁止提交订单。暂不采用，因为这会改动 D 的交易闭环边界。

### Decision 4: 使用局部样式完成体验增强

只修改 `MerchantDetailView.vue` 的 scoped CSS，避免改全局样式造成冲突。

## Proposed UI Behavior

### 店铺头部

展示：

- 商家名称
- 分类标签
- 评分
- 地址
- 营业时间
- 人均价
- 起送价
- 配送费
- 配送范围
- 收藏按钮

推荐布局：

- 顶部卡片展示店名和核心指标。
- 收藏按钮放在右侧或头部操作区。
- 使用标签区分分类、评分、配送状态。

### 配送信息

展示：

- 当前定位地址
- 距离或路线距离
- 预计送达分钟数
- 是否可配送
- 选择位置/重新定位入口

降级：

- 没有位置时显示“选择位置查看配送”。
- 定位失败时保留商家浏览和商品列表。

### 商品列表

展示：

- 商品名称
- 商品描述
- 价格
- 库存或售罄状态
- 商品图片或占位色块
- 加入按钮

交互：

- 售罄商品按钮禁用。
- 加入购物车成功后保留当前页面并提示。
- 商品为空时显示空状态。

### 状态反馈

需要处理：

- 页面加载中
- 商家详情加载失败
- 商品为空
- 收藏/取消收藏操作中
- 加入购物车失败
- 配送估算失败

## Backend Behavior

允许的小范围后端检查：

- 确认 `Product` 公开列表包含 `description`, `image`, `stock`, `price`, `status`。
- 如发现字段已存在但前端未使用，只改前端。

图片字段 `product.image` 已存在，本次仅作为展示字段使用；如果为空，前端显示占位。

## Risks / Trade-offs

- [Risk] 详情页加入太多信息导致拥挤 -> Mitigation: 使用分区和标签，把核心信息放头部，次要信息放说明区。
- [Risk] 配送状态被误解为下单限制 -> Mitigation: 文案只提示“配送状态”，不改变提交订单规则。
- [Risk] 收藏接口失败导致状态不一致 -> Mitigation: 操作完成后重新加载收藏状态，失败时显示消息。
- [Risk] 图片路径不可用 -> Mitigation: 提供本地占位块，不依赖真实图片资源。
- [Risk] 地图/定位失败 -> Mitigation: 保留商品浏览，展示手动选择位置入口。
