## Context

当前用户端已经具备首页商家浏览、团购页、购物车、订单、预约、个人中心、公告等页面，但入口和信息层级较散：

- `HomeView.vue` 承载附近商家搜索、定位、地址选择和商家卡片。
- `ProfileView.vue` 承载地址、收藏、团购券和通知。
- `LocationSelector.vue` 支持自动定位、手动省市区选择、详细地址输入和可选保存地址。
- 自动定位成功后会更新 `LocationSelector` 内部 `current`，但个人中心地址表单只在用户点击“确定并使用此位置”后通过 `confirm` 事件同步到收货地址预览；用户容易误以为自动定位已经填好可保存的收货地址。
- 个人中心地址保存目前只校验经纬度，联系人和电话缺少前端必填校验。
- 用户端路由已有 `/home`, `/deals`, `/bookings`, `/cart`, `/orders`, `/profile`, `/user/announcements`，可以在不改业务模型的情况下重组导航和个人中心分区。

目标体验：

```text
用户进入用户端
  -> 顶部/底部导航清楚区分外卖、团购、预订/到店、我的
  -> 用户在地址表单点击自动定位
  -> 页面立即展示自动定位得到的完整收货地址和坐标预览
  -> 用户补充或确认联系人、联系电话、详细门牌
  -> 只有联系人、联系电话、收货地址都完整时才能保存
  -> 我的页面按订单、购物车、优惠券/团购券、地址、收藏、消息等分组展示
```

## Goals / Non-Goals

**Goals:**

- 让自动定位后的地址同步行为与手动选择位置一致。
- 明确联系人、联系电话、收货地址为必填项。
- 在地址表单和可选保存地址表单中提供清晰校验提示。
- 改善用户端导航结构，把高频功能按业务心智分组。
- 给个人中心增加更清晰的分页或分区建议，便于后续实现。
- 优先复用现有路由、页面和 API。

**Non-Goals:**

- 不改变订单、支付、退款、配送费计算等交易规则。
- 不新增优惠券数据库模型；当前可先将“优惠券/券包”承载为团购券和未来优惠券入口。
- 不重做商家端、管理端导航。
- 不强制引入新的 UI 框架或地图服务。
- 不要求新增数据库字段。

## Decisions

### Decision 1: 自动定位成功后立即同步并预览地址

`LocationSelector.locateCurrent()` 成功后应像手动选择一样更新 `current`、触发 `update:modelValue`，并让父组件能够显示已选收货地址。推荐在自动定位完成后调用统一的同步方法，而不是只等待用户点击确认。

用户仍可编辑详细街道/门牌，并点击“确定并使用此位置”完成最终确认。

备选方案：保持自动定位只更新选择器内部状态，要求用户再点击确认。暂不采用，因为用户需求明确要求自动定位后自动显示在收货地址中。

### Decision 2: 地址保存做前端必填校验，后端可选兜底

`ProfileView.submitAddress()` 应在调用 `createAddress` 或 `updateAddress` 前校验：

- `contactName.trim()`
- `phone.trim()`
- `address.trim()`
- `longitude` 和 `latitude`

`LocationSelector.saveAddress()` 也应校验联系人、电话和地址。后端如果已有非空约束或 DTO 校验，可以保持；如果没有，可在 apply 阶段补最小校验。

备选方案：只依赖后端报错。暂不采用，因为前端即时反馈更适合表单场景，也能减少无效请求。

### Decision 3: 用户端采用“业务入口 + 我的”导航模型

建议的用户端一级导航：

- 外卖：附近商家、分类、可配送筛选、购物车快捷入口。
- 团购：团购券/套餐浏览与到店消费。
- 预订/到店：预约服务、到店履约类功能；如果当前项目只弱支持预约，可以作为次级入口。
- 消息：平台公告、系统通知；也可在“我的”中保留消息摘要。
- 我的：订单、购物车、券包、地址、收藏、个人资料。

落地时可以先保持现有页面文件，新增导航配置或局部 tab，而不是立刻拆分大量新页面。

备选方案：把所有用户功能继续放在首页和个人中心。暂不采用，因为页面会继续变长，用户不容易判断“我要点哪里”。

### Decision 4: 个人中心按任务分区，必要时用 tabs

个人中心建议从当前双列卡片改为更明确的分组：

- 我的交易：全部订单、待支付、待接单/配送中、待评价、退款/售后入口。
- 我的购物：购物车、常买/收藏商家、浏览历史可作为未来项。
- 我的券包：团购券、优惠券、可用/已用/过期状态。
- 地址与资料：收货地址、默认地址、联系人、账号资料。
- 消息与服务：通知、公告、客服/反馈可作为未来项。

当前迭代可以先做 tabs 或分区导航，把已有地址、收藏、团购券、通知迁入清晰分组；订单和购物车可以先提供跳转卡片，避免改动其业务页面。

备选方案：新建完整“我的订单”“我的购物车”“我的优惠券”子页面。可作为后续版本，但本次会增加路由和页面维护成本。

## Risks / Trade-offs

- [Risk] 自动定位出来的地址缺少门牌号，用户直接保存后不够精确 -> Mitigation: 自动填充并展示地址，但保留详细地址输入和确认按钮，文案提示补充门牌。
- [Risk] 经纬度为 `0` 时被误判为空 -> Mitigation: 校验时使用 `value !== null && value !== undefined`，避免简单 truthy 判断。
- [Risk] 导航重组影响现有路由守卫 -> Mitigation: 优先复用现有路由和 `roles: ['USER']` 元信息，新增导航只作为展示层。
- [Risk] 个人中心 tabs 与已有 `enhance-user-profile-center` 变更冲突 -> Mitigation: apply 前确认分支状态；若该变更已实现，基于现有个人中心增强继续做 tabs/导航，而不是回退已有改动。
- [Risk] “优惠券”和“团购券”概念混淆 -> Mitigation: 当前文案可使用“券包”，其中明确展示团购券；优惠券入口标注为预留或未来功能。

## Migration Plan

无数据库迁移。

推荐实施顺序：

1. 修复 `LocationSelector` 自动定位后的同步和预览行为。
2. 增加 `ProfileView` 地址表单必填校验和 Element Plus 表单规则。
3. 同步增强 `LocationSelector` 内置保存地址表单校验。
4. 设计用户端导航配置，复用现有路由形成外卖、团购、预订/到店、消息、我的入口。
5. 调整个人中心为 tabs 或任务分区，优先使用已有数据和跳转卡片。
6. 跑前端构建并做用户端关键路径烟测：自动定位、手动选址、保存地址、导航跳转、移动端布局。
