# 服务器部署指南（上传后操作清单）

> 本文说明：将 CLAS 代码上传到 Linux 服务器后，**还需要做哪些操作**才能跑通主路径。  
> 本地四微服务联调见 [`主路径联调.md`](主路径联调.md)。

---

## 1. 上传什么、不上传什么

| 建议上传 | 不要上传 |
| --- | --- |
| 整个仓库（`git clone` 优于 zip） | `services/scripts/env.local`、根目录 `.env`（含密码） |
| `services/`、`database/`、`frontend/`、`backend/` | 本机 `dump.rdb`、临时日志 |
| `services/nginx/clas-gateway.conf` | 编译产物 `target/`（可在服务器重新 `mvn package`） |

**注意**：若 `services/` 尚未提交到 git，服务器 `clone` 后只有单体 `backend/`，无法直接跑四微服务。

---

## 2. 部署形态选择

| 形态 | 适用场景 | 上传后主要操作 |
| --- | --- | --- |
| **四微服务 + Nginx** | 答辩展示架构拆分、本地同款联调 | 本文 §3–§8 |
| **单体 `backend/` jar** | 最快跑通业务 | checkout `monolith-start` 或直接用 `backend/` 构建 |
| **Docker Compose** | 单机一键、接近现有生产 | 配置 `.env` → `docker compose up -d`（见根目录 `README.md`） |
| **K8s + GitHub Actions** | 课程云端/持续部署 | 配置 Secrets → `scripts/k8s/deploy.sh`（见 `README.md`） |

四微服务的 Kubernetes 清单位于 `k8s/microservices.yaml` 和 `k8s/microservices-gateway.yaml`。它们使用
`ClusterIP`，仅通过 `clas-gateway` 暴露 API；应用前请构建并推送五个不可变标签镜像（含 `clas-merchant`），替换清单内的 `REQUIRED_TAG`，再执行：

```bash
kubectl apply -f k8s/namespace.yaml
kubectl apply -f k8s/configmap.yaml
# 使用 k8s/secret.example.yaml 创建真实 Secret 后再继续
kubectl apply -f k8s/mysql.yaml -f k8s/redis.yaml
kubectl apply -f k8s/microservices.yaml -f k8s/microservices-gateway.yaml
kubectl apply -f k8s/ingress.yaml
```

使用 `main` 分支的 GitHub Actions 部署时，不需要手工替换标签：流水线会测试、构建并导入
`clas-iam`、`clas-catalog`、`clas-order`、`clas-compat` 四个 SHA 标签镜像，再由部署脚本切换 Ingress。
须在仓库 Secret 中新增 `CLAS_INTERNAL_API_KEY`，其值应为高强度随机串，且四服务必须完全一致。

## 3. 服务器软件依赖（四微服务方案）

| 组件 | 版本建议 | 用途 |
| --- | --- | --- |
| JDK | 17+ | 运行五个 Spring Boot jar |
| Maven | 3.9+ | 构建 `services/` |
| MySQL | 8.x | 业务库 `clas` |
| Redis | 6+ | 验证码、短期缓存 |
| Nginx | 1.20+ | 统一 API 入口 `:8080` |
| Node.js | 18+（可选） | 前端 `npm run dev` 或 `npm run build` |

## 4. 环境变量

在服务器创建 `services/scripts/env.local`（参考 `services/scripts/env.local.example`）：

```bash
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=clas
MYSQL_USER=root
MYSQL_PASSWORD=替换为强密码
# 订单写隔离后：MYSQL_USER=clas_app，并增加 MYSQL_ORDER_USER / MYSQL_ORDER_PASSWORD
# 见 docs/订单域数据隔离.md

REDIS_HOST=127.0.0.1
REDIS_PORT=6379

# 五服务必须完全一致，且不得使用代码里禁用的开发默认值
JWT_SECRET=替换为至少32字符的随机串

# 五服务必须完全一致；用于 /internal/** 服务间调用，建议使用独立随机密钥
CLAS_INTERNAL_API_KEY=替换为长随机服务间密钥

# 演示/联调可选
CLAS_VERIFICATION_FIXEDCODE=123456
CLAS_DEMO_ACCOUNTS_ENABLED=true
```

启动 jar 时需让进程读到上述变量，例如：

```bash
export $(grep -v '^#' services/scripts/env.local | xargs)
java -jar services/clas-iam/target/clas-iam-0.1.0.jar
```

或在 systemd 单元文件的 `EnvironmentFile=` 中引用。

## 5. 初始化数据库

`schema.sql` 与运行时代码之间还有 migration 补丁；**不要**只导 schema 就期望所有接口可用。

### 方式 A：Linux 脚本（推荐）

```bash
cd database
export MYSQL_PASSWORD=你的密码
bash bootstrap-and-migrate.sh    # 若仓库提供
bash seed-demo.sh               # 或按需导入 seed-*.sql
```

### 方式 B：手工（与本地 bootstrap 等价）

```bash
mysql -uroot -p -e "DROP DATABASE IF EXISTS clas; CREATE DATABASE clas DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -uroot -p clas < database/schema.sql

# 按需依次导入（顺序见 database/ 下文件名）
mysql -uroot -p clas < database/seed-rider-demo.sql

# 骑手/订单相关列（示例，完整列表见 services/scripts/bootstrap-db.ps1）
mysql -uroot -p clas < database/migration-20260825-rider-delivery.sql
mysql -uroot -p clas < database/migration-20260826-order-lifecycle.sql
```

### 演示账号（`seed-rider-demo.sql`）

| 角色 | 手机号 | 密码 |
| --- | --- | --- |
| 用户 | `13345678900` | `Abc123!` |
| 商家 | `13345678901` | `Abc123!` |
| 管理员 | `13345678902` | `Abc123!` |
| 骑手 | `13345678903` / `13345678904` | `Abc123!` |

登录验证码可填 `123456`（需配置 `CLAS_VERIFICATION_FIXEDCODE`）。

## 6. 构建并启动五微服务

```bash
cd services
mvn -q package -DskipTests
```

五个进程：

```bash
cd services
java -jar clas-iam/target/clas-iam-0.1.0.jar          # 8081
java -jar clas-catalog/target/clas-catalog-0.1.0.jar  # 8082
java -jar clas-order/target/clas-order-0.1.0.jar      # 8083
java -jar clas-compat/target/clas-compat-0.1.0.jar    # 8084
java -jar clas-merchant/target/clas-merchant-0.1.0.jar # 8085
```

健康检查（每个端口各测一次）：

```bash
curl -s http://127.0.0.1:8081/api/health
curl -s http://127.0.0.1:8082/api/health
curl -s http://127.0.0.1:8083/api/health
curl -s http://127.0.0.1:8084/api/health
curl -s http://127.0.0.1:8085/api/health
```

期望：`"code":200`，`"status":"ok"`。

**生产建议**：用 systemd / supervisord 托管五个 unit，开机自启、崩溃重启。本仓库 Windows 联调脚本为 PowerShell（`start-services.ps1`），Linux 需自行编写等价 unit 或安装 PowerShell Core 后复用。

## 7. Nginx 网关（8080）

### 7.1 配置文件

使用仓库内 `services/nginx/clas-gateway.conf`，在系统 Nginx 中 `include` 或复制 `server { ... }` 块。

路由要点：

| 路径前缀 | 后端 |
| --- | --- |
| `/api/user`、`/api/address`、`/api/favorites`… | iam `:8081` |
| `/api/merchant`（不含 products） | merchant `:8085` |
| `/api/merchant/me/products`、`/api/product`、`/api/deals`（列表/发布） | catalog `:8082` |
| `/api/cart`、`/api/order`、`/api/payment`… | order `:8083` |
| `/api/rider`、`/api/admin`、`/api/public`… | compat `:8084` |

### 7.2 temp 目录（Linux 同样必须）

```bash
mkdir -p services/nginx/logs/{client_body_temp,proxy_temp,fastcgi_temp,uwsgi_temp,scgi_temp}
```

若 Nginx 以 `-p services/nginx` 为 prefix 启动，temp 路径相对于该目录下的 `logs/`。

### 7.3 验证网关

```bash
curl -s http://127.0.0.1:8080/api/health
```

## 8. 冒烟测试（等价于 `smoke-main-path.ps1`）

无 PowerShell 时，用 curl 手工验证主路径：

```bash
# 1. 网关 health
curl -s http://127.0.0.1:8080/api/health

# 2. 登录
curl -s -X POST http://127.0.0.1:8080/api/user/login \
  -H 'Content-Type: application/json' \
  -d '{"phone":"13345678900","password":"Abc123!","deviceId":"server-smoke","code":"123456"}'

# 3. 带 token 访问（将 TOKEN 替换为上一步返回值）
curl -s http://127.0.0.1:8080/api/merchant/list -H "Authorization: Bearer TOKEN"
curl -s http://127.0.0.1:8080/api/cart/me -H "Authorization: Bearer TOKEN"
curl -s http://127.0.0.1:8080/api/public/stats
```

全部返回 `"code":200` 即主路径打通。

## 9. 前端

## 10. 防火墙与安全

- 对外开放：**80/443**（Nginx 终止 TLS）或内网/demo 时 **8080**
- **勿**将 `8081–8085`、`3306`、`6379` 暴露公网
- 生产环境：禁用固定验证码、修改演示账号密码、使用强 `JWT_SECRET` 和 `CLAS_INTERNAL_API_KEY`
- 上传目录 `uploads/` 需持久化卷或对象存储（K8s 方案见 `README.md`）

## 13. 常见问题

| 现象 | 处理 |
| --- | --- |
| 四服务启动报 `JWT_SECRET` | 检查 env，勿用 `clas-dev-secret-key-2026-must-be-32bytes!` |
| 登录/查询 500，日志缺列 | 补跑 `database/migration-*.sql` 或重建库 |
| 商家列表 503 | order internal API 失败，查 `:8083` 日志与 `orders` 表结构 |
| Nginx 启动失败 | 创建 `logs/client_body_temp` 等 temp 子目录 |
| 前端 API 不通 | 确认网关 8080 已起；dev 模式看 `vite.config.js` 代理 |
| 只有 PowerShell 脚本 | Linux 用本文命令或编写 systemd；或改用 Docker/K8s |
