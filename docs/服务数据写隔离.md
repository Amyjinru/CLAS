# 各服务数据写隔离（#36 P3 / 含 #49）

目标：每张业务表只有对应服务账号可写。表仍在共享库 `clas`，空库已建、尚未 MOVE。

## 落地形态

同 MySQL 实例：

| 对象 | 作用 |
| --- | --- |
| 空库 `clas_iam` / `clas_merchant` / `clas_catalog` / `clas_order` / `clas_compat` | 后续 MOVE 用；当前无表 |
| `clas_iam_app` | iam 账号，只 ALL 自己的表 |
| `clas_merchant_app` | merchant 账号 |
| `clas_catalog_app` | catalog 账号 |
| `clas_order_app` | order 账号（#49 已有） |
| `clas_compat_app` | compat 账号 |
| `clas_app` | 遗留共享账号；P3 后对 `clas` 全表 **仅 SELECT** |

各服务数据源变量（未设置时回退 `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE`，本地默认 root 可继续联调）：

| 服务 | 用户 | 密码 | 库名 |
| --- | --- | --- | --- |
| iam | `MYSQL_IAM_USER` | `MYSQL_IAM_PASSWORD` | `MYSQL_IAM_DATABASE` |
| merchant | `MYSQL_MERCHANT_USER` | `MYSQL_MERCHANT_PASSWORD` | `MYSQL_MERCHANT_DATABASE` |
| catalog | `MYSQL_CATALOG_USER` | `MYSQL_CATALOG_PASSWORD` | `MYSQL_CATALOG_DATABASE` |
| order | `MYSQL_ORDER_USER` | `MYSQL_ORDER_PASSWORD` | `MYSQL_ORDER_DATABASE` |
| compat | `MYSQL_COMPAT_USER` | `MYSQL_COMPAT_PASSWORD` | `MYSQL_COMPAT_DATABASE` |

## 脚本

| 脚本 | 作用 |
| --- | --- |
| `database/isolate-service-privileges.sql` | 建空库、建账号、按表 GRANT |
| `database/rollback-service-privileges.sql` | 删 P3 账号与空库（保留 `clas_order_app` / `clas_app`） |
| `services/scripts/isolate-service-privileges.ps1` | 用 env.local 密码套用/回滚 |
| `services/scripts/verify-service-write-isolation.ps1` | 断言跨域写失败、本域写成功 |

```powershell
cd services/scripts
.\isolate-service-privileges.ps1
# env.local 示例：
# MYSQL_USER=clas_app
# MYSQL_IAM_USER=clas_iam_app
# MYSQL_MERCHANT_USER=clas_merchant_app
# MYSQL_CATALOG_USER=clas_catalog_app
# MYSQL_ORDER_USER=clas_order_app
# MYSQL_COMPAT_USER=clas_compat_app
# 然后重启服务
.\verify-service-write-isolation.ps1
# 回滚 P3（#49 账号仍在）
.\isolate-service-privileges.ps1 -Rollback
```

管理员账号用 `MYSQL_ADMIN_USER` / `MYSQL_ADMIN_PASSWORD`（默认 root / `MYSQL_PASSWORD`）。

`bootstrap-db.ps1` 重建 `clas` 后须再跑 isolate，GRANT 才会回到新库。

`isolate-order-privileges.ps1` 只覆盖订单四表；在 P3 之后再跑它会把 `clas_app` 的非订单表写权限加回去，不要混用。

表归属见 `docs/三服务数据表归属表.md`。订单四表细节仍见 `docs/订单域数据隔离.md`。

## 集群

`k8s/configmap.yaml` 默认仍是 `MYSQL_USER=clas`。在集群 MySQL 执行 isolate 后：

1. ConfigMap 增加 `MYSQL_IAM_USER=clas_iam_app` 等五服务账号
2. Secret 使用对应 `MYSQL_*_PASSWORD`（`deploy.sh` 已支持，缺省等于 `MYSQL_PASSWORD`）
3. 滚动五服务

未跑 isolate 前不要改 ConfigMap，否则 Pod 连不上库。物理 MOVE 表不是本轮范围。
