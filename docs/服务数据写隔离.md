# 各服务数据写隔离（#36 P3 / 含 #49）

目标：每张业务表只有对应服务账号可写，并且表在该服务的私有库中。

## 落地形态

同 MySQL 实例：

| 对象 | 作用 |
| --- | --- |
| `clas_iam` / `clas_merchant` / `clas_catalog` / `clas_order` / `clas_compat` | 各服务私有库；业务表已 MOVE 进来 |
| `clas` | 仅留 `migration_history` 等引导对象；mysql 镜像初始化库名 |
| `clas_iam_app` 等 | 只 ALL 自己的库 |
| `clas_app` | 对各私有库 **仅 SELECT** |

跨域外键 `order_item.product_id → product.id` 在 MOVE 时删除；商品存在性由 catalog 内部 API 保证。

各服务数据源变量（未设置时回退 `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE`）：

| 服务 | 用户 | 密码 | 库名 |
| --- | --- | --- | --- |
| iam | `MYSQL_IAM_USER` | `MYSQL_IAM_PASSWORD` | `MYSQL_IAM_DATABASE` |
| merchant | `MYSQL_MERCHANT_USER` | `MYSQL_MERCHANT_PASSWORD` | `MYSQL_MERCHANT_DATABASE` |
| catalog | `MYSQL_CATALOG_USER` | `MYSQL_CATALOG_PASSWORD` | `MYSQL_CATALOG_DATABASE` |
| order | `MYSQL_ORDER_USER` | `MYSQL_ORDER_PASSWORD` | `MYSQL_ORDER_DATABASE` |
| compat | `MYSQL_COMPAT_USER` | `MYSQL_COMPAT_PASSWORD` | `MYSQL_COMPAT_DATABASE` |

## 脚本

| 脚本 | 作用 |
| --- | --- |
| `database/isolate-service-privileges.sql` | 建库、建账号、GRANT |
| `database/move-service-tables.sql` | 把 `clas` 业务表搬进私有库（幂等） |
| `database/rollback-move-service-tables.sql` | 表搬回 `clas` |
| `database/rollback-service-privileges.sql` | 删 P3 账号与空私有库（保留 `clas_order_app` / `clas_app`） |
| `database/apply-service-isolation.sh` | 集群 migrate Job 调用；无 `CLAS_APPLY_SERVICE_ISOLATION=true` 则跳过 |
| `services/scripts/isolate-service-privileges.ps1` | 本机套用 isolate + MOVE / 回滚 |
| `services/scripts/verify-service-write-isolation.ps1` | 断言跨库写失败、本库写成功 |

```powershell
cd services/scripts
.\isolate-service-privileges.ps1
# env.local：MYSQL_*_USER=clas_*_app 且 MYSQL_*_DATABASE=clas_*
.\verify-service-write-isolation.ps1
# 回滚（先搬表再删账号）
.\isolate-service-privileges.ps1 -Rollback
```

`bootstrap-db.ps1` 重建 `clas` 后须再跑 isolate，表才会 MOVE 到私有库。

## 集群

`k8s/configmap.yaml`：

- `MYSQL_USER=clas`、`MYSQL_DATABASE=clas` 只给 mysql 镜像初始化用，不要改成 app 账号。
- Java 服务使用 `MYSQL_IAM_USER=clas_iam_app`、`MYSQL_IAM_DATABASE=clas_iam` 等。
- Secret 里 `MYSQL_*_PASSWORD` 缺省等于 `MYSQL_PASSWORD`（`deploy.sh` 已写入）。
- `clas-db-migrate` 设置 `CLAS_APPLY_SERVICE_ISOLATION=true`，在 `bootstrap-and-migrate.sh` 末尾跑 isolate + MOVE，先于滚动 Java。
- Compose 单体冒烟不设置该开关，表留在 `clas`，避免 `backend` 健康检查失败。

MOVE 之后新增 `migration-*.sql` 必须带库名前缀（如 `ALTER TABLE clas_order.orders ...`）。`migrate.sh` 仍连 `clas`，只为读写 `migration_history`。
