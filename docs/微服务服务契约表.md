## 2. 数据归属契约

| 主写服务 | 唯一可写表 | 其它服务的访问方式 |
| --- | --- | --- |
| 订单履约服务 | `orders`、`order_item`、`order_lifecycle_event`、`order_refund_dispute` | 只能调用订单服务 API 或消费订单事件；不得直接读写这些表或联表 |

## 3. 网关与公开 API 契约

| 公开路径前缀 | 目标服务 | 兼容规则 |
| --- | --- | --- |
| `/api/order/**` | `order-service` | 保持现有前端请求路径、方法、成功响应与业务错误语义 |
| `/api/product/**` | `catalog-service` | 保持现有前端请求路径、方法、成功响应与业务错误语义 |
| `/api/merchant/**` | `merchant-service` | 保持现有前端请求路径、方法、成功响应与业务错误语义 |
| `/api/health` | `gateway` | 不要求登录；用于入口、部署和故障排查 |

网关负责校验外部 Bearer JWT、生成或透传 `X-Request-Id`、路由、限流与服务不可用响应。业务服务仍必须自行校验角色和资源归属，不能仅依赖网关。

## 4. 统一请求、认证与失败处理

| 项目 | 固定约定 |
| --- | --- |
| 用户认证 | 受保护公开请求使用 `Authorization: Bearer <JWT>`；网关校验后向下游原样透传该请求头 |
| 内部认证 | 内部接口必须携带 `X-Service-Token`；令牌通过 Compose/Kubernetes Secret 注入，不提交仓库、不写入日志 |
| 请求追踪 | 客户端提供 `X-Request-Id` 时原样透传；否则网关生成 UUID。网关、下游响应和日志均必须包含该字段 |
| 超时 | 服务间 HTTP 连接超时 1 秒、读取超时 3 秒；超时不得继续等待或产生部分状态变更 |
| 限流 | 网关按用户 ID；未登录时按客户端 IP 限流。超限返回 HTTP 429、业务码 `RATE_LIMITED` 与 `requestId` |
| 下游不可用 | 下游超时、连接失败或熔断打开时，返回 HTTP 503、业务码 `SERVICE_UNAVAILABLE`、`requestId`；不得泄露内部地址、堆栈或密钥 |
| 写操作幂等 | 外部写操作可携带 `Idempotency-Key`；支付和配送等状态回调必须携带 `eventId`，服务以事件来源与 `eventId` 去重 |

公开响应继续遵循项目既有 `Result` 包装格式；新增或调整的响应必须至少包含可定位的业务码、用户可读消息和 `requestId`。

## 5. 订单跨服务内部 API

内部 API 均不经公网 Ingress 暴露，路径统一采用 `/internal/{service}/v1/**`。除本表列出的调用方外，拒绝访问。

| 调用方 | 提供方 | 方法与路径 | 目的 | 请求最小字段 | 成功响应最小字段 | 失败处理 |
| --- | --- | --- | --- | --- | --- | --- |
| 订单服务 | 商品目录服务 | `POST /internal/catalog/v1/order-items/validate` | 校验商品可售、价格和库存，生成下单快照 | `merchantId`、`items[{productId, quantity}]`、`requestId` | `items[{productId, name, unitPrice, quantity, available}]` | 不可售返回 `CATALOG_ITEM_UNAVAILABLE`；超时按统一 503 处理 |
| 订单服务 | 商品目录服务 | `POST /internal/catalog/v1/stock-reservations` | 创建库存预占或扣减记录 | `orderId`、`items[{productId, quantity}]`、`idempotencyKey`、`requestId` | `reservationId`、`status` | 失败时订单不得创建或推进支付状态；允许按幂等键重试 |
| 订单服务 | 商家服务 | `GET /internal/merchants/v1/{merchantId}/order-eligibility` | 校验商家存在、营业及配送资格 | `merchantId`、`deliveryLongitude`、`deliveryLatitude`、`requestId` | `merchantId`、`merchantName`、`open`、`deliveryEligible`、`deliveryFee` | 不营业或不支持配送返回 `MERCHANT_NOT_ELIGIBLE`；超时按统一 503 处理 |
| 支付服务 | 订单服务 | `POST /internal/orders/v1/events/payment-succeeded` | 通知支付成功，推进订单状态 | `eventId`、`orderId`、`paidAt`、`requestId` | `orderId`、`status`、`duplicate` | 相同来源和 `eventId` 只生效一次；非法状态返回 `ORDER_STATE_INVALID` |
| 配送服务 | 订单服务 | `POST /internal/orders/v1/events/delivery-completed` | 通知配送完成，推进订单状态 | `eventId`、`orderId`、`deliveredAt`、`riderId`、`requestId` | `orderId`、`status`、`duplicate` | 相同来源和 `eventId` 只生效一次；骑手或状态不匹配返回 `ORDER_STATE_INVALID` |

## 6. 最小验证与证据

| 验收项 | 必须保留的证据 |
| --- | --- |
| 独立运行 | 每个服务的构建、测试、容器启动和 `GET /api/health` 成功记录 |
| 网关兼容 | 经网关访问订单、商品、商家三类公开路径的 API 或端到端测试报告 |
| 安全 | 缺失/过期 JWT、无效服务令牌、跨角色或跨资源访问被拒绝的测试记录 |
| 韧性 | 限流、下游超时或停止一个服务时的 HTTP 响应、`X-Request-Id`、网关/服务日志和恢复步骤 |
| 数据隔离 | 表 owner 清单、内部调用代码或配置审查记录，证明没有跨服务 SQL 与跨库联表 |

## 7. 变更规则

修改服务名、端口、公开路径、内部路径、请求/响应字段、认证头、超时或错误码前，必须由受影响的服务负责人共同确认，并同步更新本表、OpenSpec、网关配置、部署清单和测试。
