## UC01 用户注册、登录与账号恢复

- **参与者**：游客、注册用户。
- **业务目标**：获得或恢复可认证的平台账号。
- **触发条件**：游客需要使用平台；用户忘记密码。
- **前置条件**：Redis 验证码服务可用；手机号未被占用或用户已存在且未禁用。
- **主成功流程**：
  1. 用户请求注册或找回密码验证码。
  2. 输入手机号、验证码和符合规则的密码。
  3. 系统校验验证码、手机号唯一性和密码规则。
  4. 系统创建/更新用户，使用 BCrypt 保存密码。
  5. 用户登录，系统签发 JWT 并返回身份信息。
- **备选/异常流程**：验证码错误或过期；手机号重复；密码不符合规则；账号禁用；密码错误；Token 无效或过期。
- **可验证结果**：密码以哈希形式保存；成功登录返回有效 JWT；私有接口在未认证时返回 401。
- **涉及模块**：`UserController`、`UserService`、`JwtUtil`、Redis、`user` 表、登录/找回密码页面。
- **建议测试**：密码规则和 JWT 做单元测试；注册/登录/找回做 API 集成测试；登录后访问受限页面做 E2E。

## UC02 用户维护个人资料与收货/支付资料

- **参与者**：用户。
- **业务目标**：维护交易履约所需的个人资料、收货地址和支付资料。
- **触发条件**：用户修改资料；下单前维护地址或银行卡。
- **前置条件**：用户已登录。
- **主成功流程**：
  1. 用户进入个人中心或设置页。
  2. 查看或修改昵称、头像、手机号、密码、地址、银行卡。
  3. 系统验证身份、验证码、格式和数据归属。
  4. 保存资料；用户可设定默认地址。
- **备选/异常流程**：验证码错误；手机号/密码格式不合法；试图修改其他用户的地址或银行卡。
- **可验证结果**：仅当前用户数据被更新；默认地址唯一；其他账号无法读取或修改私有资料。
- **涉及模块**：`UserProfileController`、`AddressController`、`UserBankCardController`、`user_address`、`user_bank_card`。
- **建议测试**：归属校验、默认地址唯一性单元测试；资料与地址 CRUD API 测试；个人中心 E2E。

## UC03 浏览商家并完成商品下单履约闭环

- **参与者**：用户、商家。
- **业务目标**：用户从浏览商家到支付、接单、配送、完成订单，形成可评价的交易闭环。
- **触发条件**：用户产生购买商品需求。
- **前置条件**：用户已登录；商家营业；商品有效且库存充足；存在可用收货地址。
- **主成功流程**：
  1. 用户搜索/筛选商家，查看商家与商品。
  2. 用户加入购物车并调整数量。
  3. 系统校验购物车、库存、配送和优惠条件。
  4. 用户提交订单并完成模拟支付。
  5. 商家接单、配送；用户确认完成。
  6. 系统更新订单、支付、库存和通知记录。
- **备选/异常流程**：商品下架或库存不足；购物车失效；重复支付；商家拒单；用户取消；订单超时未支付；越权查看订单。
- **可验证结果**：订单状态按规则流转；支付具备幂等性；订单仅对所属用户、商家或管理员可见；库存和通知正确。
- **涉及模块**：`MerchantController`、`ProductController`、`CartController`、`OrderController`、`PaymentController`、`OrderService`、`PaymentService`、`cart`、`orders`、`order_item`、`payment`、`notification`。
- **建议测试**：库存/状态机/幂等性单元测试；下单支付和权限 API 测试；用户下单至商家履约的全链路 E2E。

## UC04 用户申请订单退款，商家审核处理

- **参与者**：用户、商家。
- **业务目标**：用户对符合条件的订单申请退款，由所属商家审核。
- **触发条件**：用户发起售后退款。
- **前置条件**：用户已登录且为订单所属人；订单状态允许退款。
- **主成功流程**：
  1. 用户在订单详情提交退款原因。
  2. 系统记录退款申请并通知商家。
  3. 所属商家查看申请并批准或拒绝。
  4. 系统更新订单/支付状态并通知用户。
- **备选/异常流程**：订单不属于当前用户；订单状态不允许退款；非所属商家审核；重复审核。
- **可验证结果**：退款状态完整可追溯；跨店商家无法处理；用户收到处理结果。
- **涉及模块**：`OrderController`、`OrderService`、`PaymentService`、`NotificationService`、订单和支付相关表。
- **建议测试**：退款状态机与归属单元测试；申请、批准、拒绝 API 测试；用户申请至商家处理 E2E。

## UC05 用户收藏商家并接收业务通知

- **参与者**：用户。
- **业务目标**：保存感兴趣商家并查看、管理业务状态通知。
- **触发条件**：用户浏览商家；订单、退款、团购、预约、评价等业务状态变化。
- **前置条件**：用户已登录。
- **主成功流程**：
  1. 用户收藏或取消收藏商家。
  2. 业务事件发生后系统生成通知。

- **备选/异常流程**：重复收藏；取消未收藏项；访问或修改其他用户通知。
- **可验证结果**：收藏与通知仅归当前用户；通知状态变更正确。
- **涉及模块**：`FavoriteController`、`NotificationController`、`FavoriteService`、`NotificationService`、`favorite`、`notification`。
- **建议测试**：收藏去重、通知归属单元测试；收藏/通知 API 测试；个人中心 E2E。

## UC06 商家入驻申请与管理员审核开店

- **参与者**：申请人、管理员。
- **业务目标**：申请人提交商家资料，经审核获得合法经营资格。
- **触发条件**：用户或游客希望成为商家。
- **前置条件**：入驻资料、手机号、银行账户等符合校验规则。
- **主成功流程**：
  1. 申请人提交商家入驻资料并完成验证码验证。
  2. 系统创建待审核商家申请。
  3. 管理员查看申请并审核。
  4. 系统记录审核人、状态变化、备注与时间。
  5. 商家获批后进入商家工作台并可营业。
- **备选/异常流程**：商家名称/电话重复；验证码错误；非法状态流转；普通用户越权审核；商家被禁用或停业。
- **可验证结果**：商家状态机正确；审核日志存在；非管理员无法审核；非营业商家不在用户侧开放。
- **涉及模块**：`MerchantController`、`MerchantService`、`MerchantStatusEnum`、`merchant`、`merchant_audit_log`、商家注册/审核页面。
- **建议测试**：状态机与角色校验单元测试；入驻、审核、日志 API 测试；申请至审核开店 E2E。

## UC07 商家维护店铺、商品与经营状态

- **参与者**：商家。
- **业务目标**：商家维护店铺资料、商品和分类，并控制经营状态。
- **触发条件**：商家更新经营信息、商品或需要临时停业。
- **前置条件**：商家已登录，且商家状态允许操作。
- **主成功流程**：
  1. 商家维护店铺资料、Logo、联系电话或收款资料。
  2. 创建、修改、上下架、删除商品和分类。
  3. 切换营业/手动停业状态。
  4. 系统校验商家归属并保存变更。
- **备选/异常流程**：非商家身份；修改其他商家商品；删除被引用资源；非法状态。
- **可验证结果**：商家只能操作自身资源；用户侧仅展示有效、营业的商家和商品。
- **涉及模块**：`MerchantController`、`ProductController`、`MerchantLogoUploadService`、`ProductService`、`merchant`、`product`、`product_category`。
- **建议测试**：资源归属和商品状态单元测试；商品管理 API 测试；商家工作台 E2E。

## UC08 用户购买、支付、使用团购券

- **参与者**：用户、商家。
- **业务目标**：用户购买团购券并支付，商家核销券码或处理退款。
- **触发条件**：用户选择在售团购商品。
- **前置条件**：用户已登录；团购在有效期且可购买；商家合法经营。
- **主成功流程**：
  1. 用户浏览团购列表与详情。
  2. 用户购买团购并支付。
  3. 系统生成团购订单和可核销凭证。
  4. 用户到店出示凭证，商家核销。
  5. 系统写入核销记录和通知。
- **备选/异常流程**：团购下架/过期；重复支付；重复核销；券不属于当前用户；退款不符合条件。
- **可验证结果**：团购订单、支付和核销记录一致；凭证仅核销一次；商家不能核销其他商家的券。
- **涉及模块**：`DealController`、`DealService`、`PaymentService`、`group_deal`、`deal_order`、`deal_redeem_log`。
- **建议测试**：券状态与重复核销单元测试；购买、支付、核销 API 测试；购买至核销 E2E。

## UC09 用户预约生活服务，商家处理预约

- **参与者**：用户、商家。
- **业务目标**：用户预约服务，商家确认、完成或取消预约。
- **触发条件**：用户产生预约需求。
- **前置条件**：用户已登录；商家可服务；预约时间满足最小提前时间。
- **主成功流程**：
  1. 用户选择商家和预约时间，提交预约。
  2. 系统校验时间与资料，创建待确认预约。
  3. 商家查看本店预约并确认。
  4. 商家完成服务或按规则取消。
  5. 系统向双方发送通知。
- **备选/异常流程**：预约时间过早；用户取消非本人预约；商家处理非本店预约；非法状态流转。
- **可验证结果**：预约状态完整流转；双方仅可访问己方业务；通知与状态一致。
- **涉及模块**：`BookingController`、`BookingService`、`service_booking`、`NotificationService`。
- **建议测试**：时间、状态和归属单元测试；预约 API 测试；用户预约至商家完成 E2E。

## UC10 用户评价订单，商家回复及互动

- **参与者**：用户、商家。
- **业务目标**：用户在完成订单后评价，商家回复，参与者进行合规互动。
- **触发条件**：订单完成；商家需回应评价。
- **前置条件**：订单已完成；用户为订单所属人；同订单尚未评价。
- **主成功流程**：
  1. 用户提交评分、文字和图片评价。
  2. 系统校验资格与内容并保存。
  3. 商家查看本店评价并回复。
  4. 用户或允许主体对评价/回复互动。
- **备选/异常流程**：订单未完成；重复评价；越权回复/删除；内容不合规。
- **可验证结果**：评价与订单、用户、商家关联正确；商家评分更新；内容权限正确。
- **涉及模块**：`ReviewController`、`ReviewUploadController`、`ReviewService`、`ContentModerationService`、`review`、`review_image`、`review_reply`、`review_vote`。
- **建议测试**：评价资格和内容校验单元测试；提交/回复/互动 API 测试；完成订单后评价 E2E。

## UC11 评价举报、删除申请、处罚与申诉治理

- **参与者**：用户、商家、管理员。
- **业务目标**：平台处理违规内容，保存治理记录并提供申诉闭环。
- **触发条件**：用户举报内容；商家申请删评；管理员发现违规；被处罚用户提出申诉。
- **前置条件**：目标内容存在；操作者已登录；管理员具备治理权限。
- **主成功流程**：
  1. 用户举报评价/回复，或商家提交删除申请。
  2. 管理员查看举报、删除申请及历史记录。
  3. 管理员处理举报、删除内容或驳回申请。
  4. 必要时施加处罚。
  5. 用户提交申诉，管理员复核并作出决定。
- **备选/异常流程**：重复举报；目标不存在；普通用户越权处理；处罚撤销；申诉不符合条件。
- **可验证结果**：治理决定、删除备份、处罚和申诉均可追溯；权限隔离明确。
- **涉及模块**：`ReviewController`、`AdminController`、`AppealService`、`PenaltyService`、`review_delete_request`、`deleted_review_backup`、`user_penalty`、`appeal`。
- **建议测试**：权限和状态转换单元测试；举报、处罚、申诉 API 测试；举报至管理员处理的 E2E。

## UC12 用户与商家围绕业务进行消息咨询

- **参与者**：用户、商家、管理员。
- **业务目标**：用户就商家或订单咨询，商家回复，管理员按权限查看会话。
- **触发条件**：用户发起商家咨询或订单沟通。
- **前置条件**：用户已登录；目标商家/订单存在；参与者有会话访问权限。
- **主成功流程**：
  1. 用户发起商家咨询或订单消息。
  2. 系统保存消息与会话关联。
  3. 商家查看并回复客户消息。
  4. 管理员按治理权限查看会话。
- **备选/异常流程**：访问非本人订单会话；商家访问非本店客户；发送空/非法消息。
- **可验证结果**：消息按参与者和商家隔离；会话历史可查询。
- **涉及模块**：`ChatController`、`ChatService`、`chat_message`、商家消息页、管理端消息页。
- **建议测试**：会话归属单元测试；发送/查询 API 测试；用户咨询与商家回复 E2E。

## UC13 平台公告发布、展示与有效期管理

- **参与者**：管理员、用户、商家。
- **业务目标**：管理员管理运营公告，用户和商家查看当前有效公告。
- **触发条件**：平台需发布运营、规则或系统通知。
- **前置条件**：管理员已登录。
- **主成功流程**：
  1. 管理员创建公告并设定内容、置顶和有效期。
  2. 系统保存，并按有效期过滤展示。
  3. 用户/商家查看有效公告。
  4. 管理员修改或删除公告。
- **备选/异常流程**：普通用户管理公告；公告过期；时间范围非法。
- **可验证结果**：仅管理员可管理公告；前台不展示无效公告；置顶排序正确。
- **涉及模块**：`AnnouncementController`、`AnnouncementService`、`announcement`。
- **建议测试**：有效期/排序/权限单元测试；公告管理 API 测试；前台展示 E2E。

## UC14 管理员运营监管与数据导出

- **参与者**：管理员。
- **业务目标**：管理员监管用户、商家、订单和评价，并导出运营数据。
- **触发条件**：管理员进行运营、风险处置或数据汇总。
- **前置条件**：管理员已登录。
- **主成功流程**：
  1. 管理员按条件查询用户、商家、订单和评价。
  2. 管理员启停用户、审核商家、处理评价。
  3. 管理员导出用户、订单或评价 CSV。
  4. 系统返回与查询范围相符的数据和操作结果。
- **备选/异常流程**：非管理员访问；分页/筛选参数非法；导出结果为空。
- **可验证结果**：权限被严格限制；导出内容与查询范围一致；管理操作实际影响业务状态。
- **涉及模块**：`AdminController`、`MerchantController`、`StatisticsService`、管理后台、相关业务表。
- **建议测试**：RBAC 单元测试；管理与导出 API 测试；管理员后台 E2E。

## UC15 商家/管理员查看经营分析与平台统计

- **参与者**：商家、管理员。
- **业务目标**：商家掌握本店经营状况，管理员掌握平台整体指标。
- **触发条件**：经营决策、汇报或运营分析需要。
- **前置条件**：对应角色已登录；存在可统计数据。
- **主成功流程**：
  1. 商家查看本店订单、销售、商品等统计。
  2. 管理员查看平台仪表盘、订单趋势、销售趋势及排行。
  3. 系统按角色和数据范围聚合、展示统计结果。
- **备选/异常流程**：普通用户越权；无数据；筛选条件不合法。
- **可验证结果**：商家仅见本店数据；管理员可见全平台数据；统计口径与原始订单一致。
- **涉及模块**：`MerchantController`、`AdminController`、`PublicStatsController`、`StatisticsService`、商家分析与管理员仪表盘。
- **建议测试**：数据范围和聚合逻辑单元测试；统计 API 测试；管理员/商家统计页 E2E。

## UC16 骑手配送协同、结算与异常处理

- **参与者**：用户、商家、已审核骑手、管理员。
- **业务目标**：在已支付的订单上完成商家接单、骑手领取、取餐、配送、确认收货、佣金结算与评价的可追踪闭环，并妥善处理取消、超时和提现。
- **触发条件**：商家接收可配送的已支付订单；骑手上线后从任务池领取订单。
- **前置条件**：用户、商家和骑手均已登录；骑手身份已审核并处于上线、开始接单状态；订单已支付且处于允许商家接单的状态；骑手未超过同时配送容量。
- **主成功流程**：
  1. 商家接单，系统记录备餐时间和承诺送达窗口，将订单投放为 `AVAILABLE`。
  2. 骑手更新位置、开始接单，在附近任务池查看并领取可配送订单。
  3. 系统以原子方式校验骑手身份、在线和接单状态、容量、距离及订单状态；校验通过后绑定骑手，订单进入 `ASSIGNED_WAITING_MEAL`。
  4. 骑手到店，并在商家出餐后确认取餐；订单进入 `DELIVERING`。用户可在授权范围内查看骑手位置和预计送达时间。
  5. 配送期间，用户可向骑手发送订单消息；骑手可联系用户和商家，系统仅提供脱敏的通话号码。
  6. 骑手确认送达，系统将订单更新为 `DELIVERED`，创建待结算的配送佣金记录。
  7. 用户确认收货，可选打赏并提交一次骑手评价；系统将佣金和已确认小费计入骑手可提现余额。
  8. 骑手查询收入、评价和日表现并申请提现；管理员审核申请并保留资金和审核记录。
- **备选/异常流程**：骑手未审核、未上线、未开始接单、超出容量、距离不符合要求或订单已被领取时拒绝领取；骑手取餐前放弃任务时释放订单并增加改派计数，取餐后不得放弃；用户取餐前取消订单时释放骑手，取餐后取消转入既有售后流程；地图路线服务不可用时使用直线距离估算 ETA 并标记降级，但配送不中断；超过承诺时间未送达时仅生成一次超时异常和绩效/佣金扣减；送达后会话仅可查看历史，重复打赏、评价、结算、提现审批或超时扫描均不得重复记账或扣罚。
- **可验证结果**：订单状态按 `AVAILABLE → ASSIGNED_WAITING_MEAL → DELIVERING → DELIVERED` 流转并保留时间线；一个订单只能由一个骑手成功领取；无关账户不能读取实时位置、订单会话或完整电话号码；一笔订单最多产生一条佣金结算、一笔确认小费、一次骑手评价和一次超时扣罚；骑手待结算、可提现和冻结余额可从结算与提现记录完整追溯。
- **涉及模块**：`RiderController`、`RiderDeliveryController`、`RiderContactController`、`RiderMerchantContactController`、`RiderDispatchService`、`RiderDeliveryService`、`RiderLocationService`、`DeliveryTrackingService`、`RiderContactService`、`RiderSettlementService`、`RiderWithdrawalService`、订单配送字段、骑手位置/消息/结算/提现/异常相关表。
- **建议测试**：骑手容量、订单状态机、结算幂等性和权限边界做单元测试；抢单原子性、位置/会话越权、取消和提现审核做 API 集成测试；商家接单到骑手送达、用户确认与结算做跨角色 E2E。
