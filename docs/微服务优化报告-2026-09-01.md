# 微服务优化报告（2026-09-01）

## 1. 本次目标

以“数据由所属服务管理、跨服务只能使用受控内部契约”为统一规范，收敛目录、订单和兼容服务对 IAM 数据的直接读取；同时保持既有 JWT、角色、单设备会话与账户限制行为。

## 2. 已完成优化

| 范围 | 统一后的实现 | 结果 |
| --- | --- | --- |
| 服务间鉴权 | `/internal/**` 统一要求 `X-CLAS-Service`、`X-CLAS-Internal-Key` | 未认证内部调用返回 `401 / INTERNAL_UNAUTHORIZED` |
| IAM 鉴权契约 | 新增 `GET /internal/iam/v1/users/{userId}/auth-state` | 一次返回账号状态、当前会话、已授权/兼容角色和账户限制状态 |
| catalog / order / compat 外部请求鉴权 | 统一为 JWT 本地验签后调用 IAM `auth-state` | 删除三个服务中仅用于鉴权的 `UserMapper`、`UserRoleMapper`、会话触达与处罚查询服务 |
| compat 跨域查询 | 公开统计、商家身份校验、骑手隐私通话手机号走 catalog / IAM 内部 API | 相应路径不再直接查询商品、商家或用户表 |
| 契约文档 | 团购路由、internal 认证头、auth-state 契约统一记录 | 文档与网关及代码一致 |

## 3. 测试证据

执行命令：

```powershell
cd services
mvn --batch-mode clean test
```

结果：**BUILD SUCCESS**，六个 Maven 模块均完成编译与测试。

| 测试类 | 覆盖内容 | 结果 |
| --- | --- | --- |
| `InternalServiceAuthInterceptorTest` | 正确服务凭据、错误密钥、缺少服务名 | 2 / 2 通过 |
| `AuthInterceptorTest`（catalog） | IAM 当前会话接受、旧会话拒绝 | 2 / 2 通过 |

首次测试发现 JDK 24 与现有 Mockito/Byte Buddy 的动态 mock 组合不兼容；测试已改为真实 JWT 与轻量假 IAM 客户端，不再依赖动态字节码代理，随后全量测试通过。

本机没有 `services/scripts/env.local`，因此未启动依赖 MySQL 和 Redis 的四服务主路径冒烟测试。部署环境应补充执行 `services/scripts/smoke-main-path.ps1`，覆盖登录、目录浏览、下单、团购、配送与异常链路。

## 4. 当前遗留风险

1. 四服务仍共享 `clas` 库和数据库账号，尚未具备数据库级最小权限隔离。
2. compat 的配送、派单、结算等仍直接读取订单/目录表；应优先以 `/internal/order/v1/**` 和 `/internal/catalog/v1/**` 补齐配送所需快照契约。
3. compat 的骑手申请、处罚、申诉和资料模块仍有 IAM Mapper 依赖；应迁移为 IAM 命令与查询接口。
4. 订单调用目录库存扣减仍为同步 HTTP，缺少 Outbox、持久化补偿任务与操作幂等号，服务在远端扣减后崩溃时存在不一致风险。
5. 内部调用目前使用共享密钥；生产环境应升级为每服务独立凭据、调用方白名单并优先使用 mTLS。

## 5. 下一步建议

1. 为每个服务创建最小权限数据库账号，并在迁移期先限制写权限。
2. 先拆出订单配送快照/状态命令，再迁移 compat 的配送、结算和派单代码。
3. 为库存扣减和订单创建增加业务操作号、Outbox 与补偿任务。
4. 增加 IAM、catalog、order、compat 的 API 成功、鉴权失败、上游超时和补偿测试，并在 CI 中运行。
