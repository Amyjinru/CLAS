# 订单履约端到端回归（#50）

`services/scripts/order-e2e-regression.ps1` 仅通过网关访问公开 API，并将每个请求的 HTTP 状态、业务 `code`、响应 `X-Request-Id` 与响应体写入 `docs/evidence/`。令牌不会写入证据文件。

## 正常路径与异常路径

先在共享五服务环境启动 MySQL、Redis、IAM、Merchant、Catalog、Order、Compat 与 Nginx。可复用已准备好的共享环境；本地独立执行时使用：

```powershell
pwsh services/scripts/bootstrap-db.ps1
pwsh services/scripts/start-services.ps1
```

随后运行（`MerchantId` 必须属于所给商家账号）：

```powershell
pwsh services/scripts/order-e2e-regression.ps1 `
  -MerchantPhone '<merchant phone>' -MerchantPassword '<merchant password>' -MerchantId <merchant id>
```

脚本会验证：商品可售/库存校验后的创建订单、订单项价格快照、同一 `Idempotency-Key` 的重试复用同一订单、用户越权接单返回 403、支付后的退款申请与商家审批、时间线，以及未登录创建订单返回 401。请求全部含网关路径与 `X-Request-Id`，证据 JSON 中保留响应的请求标识。

## 依赖故障验证

在正常脚本结束后重新加入一个可售商品到购物车，**仅停止 Catalog 服务**，保持 Nginx、IAM、Merchant 和 Order 服务运行，再执行：

```powershell
pwsh services/scripts/order-e2e-regression.ps1 `
  -MerchantPhone '<merchant phone>' -MerchantPassword '<merchant password>' -MerchantId <merchant id> `
  -VerifyDependencyFailure
```

此模式断言下单返回 HTTP 503、业务 `code` 503，且响应含 `X-Request-Id`。完成后恢复 Catalog 服务，并在 Issue #47 回贴该证据 JSON、Nginx access/error 日志和服务健康检查；这避免在共享环境中由脚本自行停止其他成员正在使用的服务。

## 创建订单幂等契约

`POST /api/order/create` 现在接受可选的 `Idempotency-Key`。同一用户对同一键的后续提交返回第一次创建的订单及订单项，不会再次消费购物车。键去空白后最长 128 字符；数据库使用 `(user_id, client_request_key)` 唯一索引，空键不参与历史请求的约束。部署前需执行 `database/migration-20260902-order-create-idempotency.sql`；`services/scripts/bootstrap-db.ps1` 已包含该迁移。
