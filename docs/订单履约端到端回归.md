# 订单履约端到端回归（#50）

`services/scripts/order-e2e-regression.ps1` 仅通过网关访问公开 API，并将每个请求的 HTTP 状态、业务 `code`、响应 `X-Request-Id` 与响应体写入 `docs/evidence/`。令牌不会写入证据文件。

## 正常路径与异常路径

先在共享五服务环境启动 MySQL、Redis、IAM、Merchant、Catalog、Order、Compat 与 Nginx。可复用已准备好的共享环境；本地独立执行时使用：

```powershell
pwsh services/scripts/bootstrap-db.ps1
pwsh services/scripts/start-services.ps1
```

随后运行（`MerchantId` 必须属于所给商家账号）：

```powershell
pwsh services/scripts/order-e2e-regression.ps1 `
  -MerchantPhone '<merchant phone>' -MerchantPassword '<merchant password>' -MerchantId <merchant id>
```

脚本会验证：商品可售/库存校验后的创建订单、订单项价格及商品名称/图片快照、商家名称/Logo 快照、同一 `Idempotency-Key` 的重试复用同一订单且返回原快照、用户越权接单返回 403、支付后的退款申请与商家审批、时间线，以及未登录创建订单返回 401。请求全部经网关路径，并将 `X-Request-Id`、耗时和响应体写入证据 JSON。

## 依赖故障验证

在正常脚本结束后重新加入一个可售商品到购物车，**仅停止 Catalog 服务**，保持 Nginx、IAM、Merchant 和 Order 服务运行，再执行：

```powershell
pwsh services/scripts/order-e2e-regression.ps1 `
  -MerchantPhone '<merchant phone>' -MerchantPassword '<merchant password>' -MerchantId <merchant id> `
  -FaultOnly -FaultProductId <product id>
```

此模式断言下单返回 HTTP 503、业务 `code` 503、`X-Request-Id`，并在默认 5 秒内返回。`-PrepareDependencyFailure` 可在停止 Catalog 前只完成购物车准备。为可重复的独占本机验证，可一次执行：

```powershell
pwsh services/scripts/run-shared-integration.ps1 -OrderE2E
```

该入口会启动临时依赖与五服务环境，完成正常路径、准备购物车、仅停止并重启 Catalog、验证 503，最后清理进程和临时容器。将生成的证据回链到 [#39](https://github.com/Amyjinru/CLAS/issues/39)。

## 创建订单幂等契约

`POST /api/order/create` 现在接受可选的 `Idempotency-Key`。同一用户对同一键的后续提交返回第一次创建的订单及订单项，不会再次消费购物车。键去空白后最长 128 字符；数据库使用 `(user_id, client_request_key)` 唯一索引，空键不参与历史请求的约束。部署前需执行 `database/migration-20260902-order-create-idempotency.sql` 和 `database/migration-20260902-order-snapshots.sql`；`services/scripts/bootstrap-db.ps1` 已包含两项迁移。旧订单的新增快照列为 `NULL`，读取时才回退到受控内部 Catalog/Merchant 查询；新订单不会依赖当前目录或商家资料来展示历史快照。
