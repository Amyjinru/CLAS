# 订单域数据隔离（#49 / #39 前置）

目标：四张订单域表（`orders`、`order_item`、`order_lifecycle_event`、`order_refund_dispute`）只有 `clas-order` 可写。

## 落地形态

同 MySQL 实例、表仍在 `clas`：

| 对象 | 作用 |
| --- | --- |
| 库 `clas_order` | 已创建，空库；P3 再 MOVE 表 |
| 账号 `clas_order_app` | clas-order 数据源；四表 + 订单域其他表 ALL |
| 账号 `clas_app` | 其他服务数据源；四张订单表仅 SELECT，其余 `clas` 表 ALL（脚本按表 GRANT，避免 schema 级 ALL + REVOKE 报 1147） |

clas-order 数据源变量（回退共享变量）：

- `MYSQL_ORDER_USER` / `MYSQL_ORDER_PASSWORD` / `MYSQL_ORDER_DATABASE`

未设置时仍用 `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE`，本地默认 root 可继续联调。

## 脚本

| 脚本 | 作用 |
| --- | --- |
| `database/isolate-order-privileges.sql` | 建库、建账号、订单账号 GRANT |
| `database/rollback-order-privileges.sql` | 删账号与空库 `clas_order` |
| `services/scripts/isolate-order-privileges.ps1` | 用 env.local 密码套用/回滚 |
| `services/scripts/verify-order-write-isolation.ps1` | 断言 clas_app 写失败、clas_order_app 写成功 |

```powershell
cd services/scripts
.\isolate-order-privileges.ps1
# 把 env.local 改为 MYSQL_USER=clas_app、MYSQL_ORDER_USER=clas_order_app 后重启
.\verify-order-write-isolation.ps1
# 回滚
.\isolate-order-privileges.ps1 -Rollback
```

管理员账号用 `MYSQL_ADMIN_USER` / `MYSQL_ADMIN_PASSWORD`（默认 root / `MYSQL_PASSWORD`）。

`bootstrap-db.ps1` 重建 `clas` 后须再跑 isolate，GRANT 才会回到新库。

## compat 写路径

已改为订单内部命令，不再直写：

- `POST /internal/order/v1/deliveries/{id}/claim`
- `POST /internal/order/v1/deliveries/{id}/pickup`
- `POST /internal/order/v1/deliveries/{id}/complete`
- `POST /internal/order/v1/deliveries/{id}/abandon`
- `POST /internal/order/v1/deliveries/{id}/predicted-arrival`
- `PUT /internal/order/v1/riders/{riderId}/delivery-sequence`
- `POST /internal/order/v1/lifecycle-events`

Admin/统计/聊天/结算对订单表的 **SELECT** 仍走 Mapper，截止日期 **2026-09-15**。物理拆表必须先清这些读。

## 集群

`k8s/configmap.yaml` 默认仍是 `MYSQL_USER=clas`。在集群 MySQL 执行 isolate 后：

1. ConfigMap 增加 `MYSQL_ORDER_USER=clas_order_app`，并把 `MYSQL_USER` 改为 `clas_app`
2. Secret 使用 `MYSQL_ORDER_PASSWORD`（`deploy.sh` 已支持，缺省等于 `MYSQL_PASSWORD`）
3. 滚动 clas-order 与其他服务

未跑 isolate 前不要改 ConfigMap，否则 Pod 连不上库。
