## 3. 推荐的三服务方案（小学期可落地版）

> 完整 12 服务蓝图见 `docs/microservice-design.md`。课程只需 **≥3 个业务服务**，建议先采用任务书推荐的粗粒度拆分，降低联调成本。

### 3.1 服务定义

| 服务名（建议） | 职责 | 主写表（摘自设计文档 §5） | 当前代码入口 |
| --- | --- | --- | --- |
| **clas-iam** | 登录注册、资料、地址、收藏、银行卡 | `user`, `user_role`, `user_address`, `user_bank_card`, `favorite` | `User*Controller`, `AddressController`, `Favorite*` |
| **clas-catalog** | 商家入驻/审核、商品目录、图片上传 | `merchant`, `merchant_audit_log`, `product_category`, `product` | `MerchantController`, `Product*Controller` |
| **clas-order** | 购物车、下单、支付、订单状态机、退款 | `cart`, `orders`, `order_item`, `order_lifecycle_event`, `order_refund_dispute`, `payment` | `CartController`, `OrderController`, `PaymentController` |

**暂缓独立拆分（仍留单体或第 4 个以后）**：配送骑手、运营通知、营销团购、预约、沟通、评价——可在网关后仍路由到「遗留 monolith 模块」或后续迭代。

### 3.2 跨服务调用（首批必须实现）

| 业务动作 | 调用方 | 被调方 | 接口示例 | 失败策略 |
| --- | --- | --- | --- | --- |
| 下单前校验商家/商品 | order | catalog | `GET /internal/catalog/v1/merchants/{id}`、`GET .../products/{id}` | 超时 2s → 返回「商品不可用」 |
| 创建订单后通知 | order | iam | `GET /internal/iam/v1/users/{id}/profile`（只读） | 超时 → 订单仍创建，通知异步补发 |
| 支付结果回写 | order | （内置 payment 模块或 payment 子域） | 同事务或本地事件 | 幂等键防重复 |

**禁止**：order 服务直接 `JOIN merchant` / `product` 表。

### 3.3 兼容策略

- 对外 URL **保持不变**（`/api/order/create` 等），由 **Ingress / API Gateway** 路由到对应服务。
- 迁移期可保留一个 **monolith-compat** Deployment 承接未拆模块，避免一次拆光。
- 数据库：Phase 1 仍共用一个 MySQL 实例，按 **schema 前缀** 或逻辑隔离（`iam.*`, `catalog.*`, `order.*`）；Phase 2 再拆库（时间不够可只做逻辑归属 + 代码层禁止跨库）。

#### 8.2 故障处理实验设计（待执行）

| 项 | 建议 |
| --- | --- |
| 场景 | **order** 调用 **catalog** 时，catalog Pod 缩容为 0 或 `NetworkPolicy` 拒连 |
