## 禁止示例

- order / catalog / iam / compat **不得** 注入 `MerchantMapper`；商家读写一律 `/internal/merchant/v1/**`。
- 下单需商品信息 → catalog 内部 API；需商家营业状态 → merchant 内部 API，见 `docs/跨服务调用与失败处理.md`。
- 除下方「compat 过渡写路径」外，compat **不得** INSERT/UPDATE/DELETE `orders`、`order_item`、`order_lifecycle_event`、`order_refund_dispute`。

## compat 仍直接写订单表：过渡处置与负责人

当前 `clas-compat` 骑手履约仍直写订单库（已知债，**不计入数据隔离验收**）：

| 代码 | 动作 | 表 |
| --- | --- | --- |
| `RiderService.claimForRider` | 领取任务 | UPDATE `orders` |
| `RiderDispatchService` | 派单/改派 | UPDATE `orders` |
| `RiderDeliveryService` | 取餐/送达/放弃 | UPDATE `orders` |
| `DeliveryTrackingService` | 配送轨迹字段 | UPDATE `orders` |
| `OrderLifecycleService` | 骑手事件时间线 | INSERT `order_lifecycle_event` |

**过渡规则（冻结）：**

1. **允许继续写**：仅骑手领取 / 改派 / 取餐 / 送达 / 放弃 对 `orders` 的状态字段，以及对应的 `order_lifecycle_event` 插入。不得扩大到改金额、商品行或退款争议。
2. **立即禁止**：compat 对 `order_item`、`order_refund_dispute` 的任何写；Admin 退款争议必须调 order。
3. **退出条件**：`clas-order` 提供 `/internal/order/v1` 配送命令（claim / pickup / complete / abandon）后，compat 改为 HTTP 调用并删除 `OrdersMapper` 写方法与 `OrderLifecycleEventMapper`。
4. **负责人**：订单内部配送命令与写权收回 — **#39 @skdfndh**；compat 改调并删除跨域 Mapper — **clas-compat 维护方**（与 #39 同一迭代，架构口径由 **#36 @hint314** 冻结）。物理拆库必须等本条清零。
