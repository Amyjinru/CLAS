## 2. 测试范围、策略与通过准则

### 2.1 测试类型

| 类型 | 方法 | 覆盖目标 |
| --- | --- | --- |
| 单元测试 | JUnit、Node 内置 `node:test` | 密码规则、加密脱敏、聚合规则、前端工具逻辑 |
| 后端集成/API | Spring Boot Test、MockMvc、H2 或本地 MySQL | Controller—Service—Mapper 链路、权限、状态机、幂等性 |
| API 冒烟 | Vitest/HTTP 请求脚本 | 已部署或本地服务的关键接口连通性和响应 |
| 浏览器 E2E | Playwright Chromium | 用户、商家、管理员跨页面业务闭环 |
| 手工验收 | 代表性页面、截图和操作记录 | UI 展示、导出、统计等自动化未覆盖内容 |
| 构建验证 | Maven、Vite 生产构建 | 后端测试可执行、前端可编译发布 |

### 2.2 通过与判定规则

- 自动化执行以 `Failures=0`、`Errors=0` 为通过；API 用例还需断言状态码、统一响应和关键业务数据。
- 业务拒绝场景只有在权限不足、归属不符、重复操作或非法状态转换被正确拒绝且不写入错误数据时才算通过。
- 前端生产构建成功是交付验证，不计入自动化用例数。
- 未执行的场景不得因关联模块测试通过而标记为“已覆盖”。任一 UC 存在关键专项空白时，其结论为“有条件通过”。

## 8. 复现指引

以下命令用于后续在相同或隔离环境中复跑；运行前应确认 Java、Node、依赖、Redis 与测试数据库配置正确，且不得对生产库执行测试 schema。

```powershell
# 后端全量测试
mvn --batch-mode -f backend/pom.xml test

# 前端生产构建
npm --prefix frontend run build

# UC16 专项
mvn --batch-mode -f backend/pom.xml '-Dtest=RiderModuleIntegrationTest,RiderIdentityCryptoTest' test

# UC05—UC08 API/E2E（需先启动本地前后端）
cd tests
./node_modules/.bin/vitest run --config vitest.config.js api/clas-api.spec.js
./node_modules/.bin/playwright test --config playwright.config.js clas-uc05-08.spec.js
```

执行后应保存 Maven Surefire XML、Vitest/Playwright 输出、构建日志、代表性截图及当前提交号；复跑结果不能与本报告的历史统计直接相加。
