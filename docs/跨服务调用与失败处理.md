# CLAS 跨服务调用与失败处理说明

## 1. 约定

- 对外路径仍为 `/api/*`，由 Nginx 路由到各服务。
- 服务间同步调用使用 HTTP JSON，前缀 `/internal/{service}/v1/**`，不对外暴露。
- 传递用户身份：`Authorization: Bearer <JWT>` 原样转发。
- 默认超时：**连接 1s，读取 2s**（order → catalog 故障实验场景）。

## 2. 主要调用链

| 业务 | 调用方 | 被调方 | 接口（示例） |
| --- | --- | --- | --- |
| 下单校验商品 | order | catalog | `GET /internal/catalog/v1/products/batch?ids=` |
| 下单校验商家营业 | order | catalog | `GET /internal/catalog/v1/merchants/{id}` |
| 下单校验地址 | order | iam | `GET /internal/iam/v1/users/{id}/addresses/{addressId}` |
| 买团购前查活动 | order | catalog | `GET /internal/catalog/v1/deals/{id}` |
| 下单成功通知 | order | iam | `POST /internal/iam/v1/notifications` |
| 处罚校验 | order | iam | `GET /internal/iam/v1/users/{id}/penalty-status` |
| 管理后台列表 | compat | iam/catalog/order | 各服务只读 API |

## 3. 失败处理策略

| 调用 | 失败策略 | 用户可见结果 |
| --- | --- | --- |
| order → catalog（下单/买券） | 失败即中断 | `503`「商品/活动信息暂不可用，请稍后重试」 |
| order → iam（地址/处罚） | 失败即中断 | `503`「账户或地址服务暂不可用」 |
| order → iam（发通知） | 失败记日志，订单可成功 | 无阻塞；后台补偿/人工排查 |
| compat → 三服务（admin 统计） | 部分失败降级 | 仪表盘缺项 + 明确错误字段，compat 自身 health 仍 200 |

## 4. 故障实验（任务书）

1. **注入**：`kubectl scale deployment/clas-catalog --replicas=0`
2. **预期**：`POST /api/order/create` 返回上述 503 文案；`GET /api/health`（order、iam）仍 200
3. **恢复**：scale catalog 回 1，下单恢复
4. **证据**：正常 / 故障 / 恢复 三段 curl + order 服务日志

## 5. 幂等与版本

- 支付、创建订单沿用现有幂等键；跨服务调用携带 `X-Request-Id`（`RequestTraceContext`）。
- 内部 API 变更需兼容期：旧路径保留一个迭代。
