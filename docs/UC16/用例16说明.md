# UC16 骑手配送协同

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC16 |
| 参与者 | 普通用户、商家、已审核骑手、管理员 |
| 业务目标 | 在订单支付后完成商家接单、骑手领取、取餐、配送、用户确认、结算和评价的可追踪闭环。 |
| 触发条件 | 商家对已支付订单接单并使其进入可配送状态。 |
| 前置条件 | 用户、商家和骑手均已登录；骑手 `RIDER` 身份已审核，已上线并开始接单；订单处于允许的状态。 |

## 主成功流程

1. 商家接单，系统快照备餐时间、计算承诺窗口，并将订单置为 `AVAILABLE`。
2. 骑手更新位置、开始接单，在附近任务池按佣金、距离或智能排序查看可领任务。
3. 骑手领取任务，系统原子校验身份、上线/接单状态、容量、距离和订单状态，订单进入 `ASSIGNED_WAITING_MEAL`。
4. 骑手到店并在出餐后确认取餐，订单进入 `DELIVERING`；用户可查看授权范围内的骑手位置和 ETA。
5. 配送期间，用户可与骑手沟通；骑手可联系用户、商家，隐私通话仅返回脱敏号码。
6. 骑手确认送达，订单进入 `DELIVERED`，生成待结算配送佣金。
7. 用户确认收货，可选打赏并提交一次骑手评价；佣金和已确认小费变为可提现余额。
8. 骑手查看收入、评价、日表现并发起提现；管理员审核提现和异常记录。

## 备选与异常流程

- 骑手未审核、未上线、未开始接单、超出容量、距离不满足或任务已被领取：系统拒绝领取且不修改订单归属。
- 骑手取餐前放弃：订单返回 `AVAILABLE` 并增加改派计数；取餐后不允许放弃。
- 用户取餐前取消：释放骑手但不自动改派；取餐后取消进入既有售后规则。
- 高德路线服务不可用：使用直线距离估算并标记路线降级，不阻断配送状态流转。
- 超过承诺时间未送达：仅一次生成超时异常，扣骑手绩效与佣金，不自动退款、取消或改派。
- 送达后：聊天停止写入但保留历史；重复小费、评价、结算或超时扫描均不得重复记账或扣罚。

## 可验证结果

- 订单状态依次满足 `AVAILABLE → ASSIGNED_WAITING_MEAL → DELIVERING → DELIVERED`，并保留时间线。
- 无关账户不能读取骑手实时位置、对话或完整电话号码。
- 一次订单只产生一次小费、骑手评价、佣金结算和超时扣罚。
- 骑手余额的待结算、可提现、冻结变动可从结算与提现记录追溯。
