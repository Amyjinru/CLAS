# 商品目录内部契约（#37）

> 基线：`main@38f9d43`。正式目录模块为 `services/clas-catalog`（端口 `8082`）；
> `services/catalog-service` 仅保留为弃用原型，不纳入 Maven 聚合构建、网关或 Kubernetes。

## 所有权与调用边界

- `product_category`、`product` 仅由 `clas-catalog` 写入和管理；订单仅保存商品 ID 和快照，不直接使用商品 Mapper 或商品表。
- `clas-order` 通过 `CatalogClient` 调用本页的 `/internal/catalog/v1/**`，连接超时 1 秒、读取超时 2 秒；网络或 HTTP 调用失败统一映射为 HTTP 503、`UPSTREAM_UNAVAILABLE`。
- 响应统一为 `Result<T>`：`code`、`message`、`data`、`timestamp`、`requestId`、`errorCode`。

## 商品内部接口

| 方法与路径 | 请求 | 成功响应 | 失败语义 |
| --- | --- | --- | --- |
| `GET /products/{productId}` | 路径商品 ID | `200 Result<Product>`；不存在时 `data: null` | 未授权为 `401 INTERNAL_UNAUTHORIZED` |
| `GET /products/batch?ids=1,2` | 逗号分隔 ID | `200 Result<List<Product>>`；空参数为空数组 | 非数字 ID 为 HTTP 400、`VALIDATION_ERROR`；调用方不得依赖部分成功 |
| `POST /products/{productId}/deduct-stock` | `{ "quantity": 2 }` | `200 Result<Boolean>`；`true` 表示原子扣减成功，`false` 表示商品不存在或库存不足 | `quantity <= 0` 为 HTTP 400；未授权为 HTTP 401 |
| `POST /products/{productId}/restore-stock` | `{ "quantity": 2 }` | `200 Result<Void>` | `quantity <= 0` 为兼容旧调用的无操作；未授权为 HTTP 401 |

内部调用必须同时携带 `X-CLAS-Service` 与 `X-CLAS-Internal-Key`。公共网关不转发 `/internal/**`；服务端以常量时间比较共享内部密钥。请求中的 `Authorization` 和 `X-Request-Id` 会由服务 HTTP 客户端透传。

## 验收证据

- 单模块构建入口：`mvn --batch-mode -pl clas-catalog -am package`（位于 `services/`）。
- 容器入口：`docker build -f services/Dockerfile --build-arg SERVICE_MODULE=clas-catalog services`。
- 部署入口：`k8s/microservices.yaml` 中的 `clas-catalog` Deployment/Service，以及 `k8s/catalog-hpa.yaml`。
- 回归测试：`InternalCatalogControllerContractTest` 覆盖查询、批量查询、库存成功/不足/非法数量和恢复；`ProductControllerContractTest` 覆盖公开商品查询成功及异常映射；`InternalServiceAuthInterceptorTest` 覆盖内部认证成功与拒绝。
