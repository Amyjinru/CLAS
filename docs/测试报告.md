## 1 引言

### 1.1 目标

本测试报告旨在对 CLAS 平台当前版本进行系统化的质量验证与结果归档，具体目标如下：

1. 验证用户端外卖下单闭环（浏览商家 → 购物车 → 下单 → 模拟支付 → 商家处理 → 完成 → 评价）是否按设计实现。
2. 验证商家端入驻、接单、商品管理、团购/预约/退款等核心业务能力是否可用。
3. 验证管理员端审核、统计、评价治理、公告管理等后台能力的基本正确性。
4. 验证鉴权（JWT + RBAC）、数据一致性（外键/库存/优惠券状态）及 API 规范（统一响应体、错误码、请求追踪）。
5. 为课程实验及后续迭代提供可对照、可复现的测试文档与执行记录。

### 1.2 背景

CLAS 是面向校园/本地生活场景的综合服务平台，采用 Spring Boot 3 + Vue 3 前后端分离架构，数据库含 28 张业务表，支持用户、商家、管理员三类角色。系统已实现模拟支付、Redis 验证码、优惠券、团购、预约、评价治理（举报/删评/申诉/处罚）等扩展功能。

随着功能持续迭代（如人均消费计算规则、secondary 按钮样式、通知跳转回填等），需要通过规范化测试活动确认核心流程未被破坏，并识别尚未覆盖的高风险模块，因此编制本报告。

### 1.3 范围

### 2.3 测试方法

**总体策略：测试金字塔 + 分层验证**

1. **单元测试（Unit）**  
   针对独立业务规则使用 Mockito/JUnit，如 `MerchantAveragePriceTest`、`LegacyNotificationTargetResolverTest`、`JwtUtilTest`。

2. **集成测试（Integration）**  
   使用 `@SpringBootTest` + `MockMvc` + H2 + Redis，在 `ModuleIntegrationTest` 中覆盖 44 个 API 级场景，验证 Controller → Service → Mapper 链路。

3. **前端单元测试（Frontend Unit）**  
   使用 Node.js 内置 `node:test`，对密码规则、通知路由、商家资料验证码逻辑等进行静态/轻量行为断言（不启动浏览器）。

4. **手工冒烟测试（Manual Smoke）**  
   使用 README 演示账号在浏览器中走通主流程，验证 UI 与 API 联调。

5. **可选远程测试（Optional）**  
   `tests/api/clas-api.spec.js`（Vitest）与 `tests/e2e/clas-order-flow.spec.js`（Playwright）针对部署服务器执行，本次报告以本地自动化结果为主。

**充分性判定：**

- 后端：所有 `@Test` 方法执行通过且无 Failure/Error。
- 前端：19 项 `node:test` 全部 pass。
- 核心 API：注册/登录/购物车/支付/评价/优惠券/团购/预约至少各 1 条自动化用例覆盖。
- 语句覆盖：未强制要求 Jacoco 阈值；以关键路径用例覆盖为主。

**需求跟踪：** 测试用例与 README 验收流程及 `ModuleIntegrationTest` 方法名建立映射（见第 4、6 章）。

## 3 测试设计说明

### 3.1 目的

本测试设计说明将测试计划中的方法细化为可执行的测试技术与用例设计原则，明确各特征组的输入构造、预期输出及结果分析方法。

### 3.2 详细说明

#### 3.2.1 测试设计说明标识符

**CLAS-TD-2026-001**（对应测试计划 CLAS-TP-2026-001）

#### 3.2.2 要测试的特征

本设计说明重点覆盖以下特征组合：

1. **F-AUTH + F-TRD**：用户注册登录后完成购物车与订单全流程（`paymentReviewFlowWorks`）。
2. **F-MCH + F-TRD**：商家入驻、Logo、资料验证码与订单商家视角详情。
3. **F-MKT**：优惠券、团购、预约的状态与 RBAC。
4. **F-PLT**：公告与通知 legacy 兼容。
5. **F-MCH-04**：人均消费阈值逻辑（单元测试隔离验证）。
6. **F-FE**：前端密码与通知跳转一致性。

#### 3.2.3 方法细化

| 特征 | 测试技术 | 输入构造 | 结果分析 |
| --- | --- | --- | --- |
| 注册/登录 | MockMvc POST + JSON | 随机手机号、固定验证码 `123456` | 断言 HTTP 状态、`$.code`、敏感字段不返回密码 |
| 订单/支付 | 多步 API 调用链 | 演示商家商品、用户 Token | 断言订单状态迁移、库存、支付幂等 |
| 权限 | 不同角色 Token 访问同一资源 | USER/MERCHANT/ADMIN JWT | 断言 200/403 |
| 人均消费 | Mockito 单元测试 | 模拟 0/10 笔 COMPLETED 订单及商品列表 | 断言 `averagePrice` 写入值 |
| 通知 legacy | 纯 Java 单元测试 | 构造旧版 notification 文本 | 断言解析出的 targetPath |
| 前端密码 | 读取源码/规则函数 | 合法/非法密码字符串 | `assert` 匹配后端规则 |
| 外键 | JdbcTemplate 直接插 orphan 行 | 违反 FK 的 SQL | 期望抛出约束异常 |

**共同约束：**

- 集成测试统一使用 `@ActiveProfiles("test")`。
- 验证码固定为 `123456`（`clas.verification.fixed-code`）。
- 测试用户密码统一为 `Abc123!`（满足复杂度规则）。

#### 3.2.4 特征通过准则

| 特征 | 通过 | 失败 |
| --- | --- | --- |
| API 成功调用 | `code=200` 且关键字段非空 | 非预期 4xx/5xx 或 `code≠200` |
| 业务拒绝 | 抛出预期 BusinessException 或返回明确 errorCode | 错误被吞或返回成功 |
| 状态机 | 订单/优惠券/预约状态与操作匹配 | 出现非法状态跳转 |
| 人均消费 | <10 单：商品均价；≥10 单：订单均价 | 计算错误或未刷新 |
| 前端规则 | 19 项测试 pass | 任一 fail |
